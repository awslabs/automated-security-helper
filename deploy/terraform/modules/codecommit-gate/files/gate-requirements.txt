# What the pull-request gate's Lambda image adds to the ASH image, pinned by
# version and SHA256 and installed with `pip install --require-hashes`.
#
# This one file feeds both builds of that image: gate.Dockerfile here, and the
# CDK `lambda` flavor in deploy/cdk/lib/ash-image-build.ts, which reads this file
# at synth time and writes it into its build context. They cannot drift apart;
# tests/unit/deploy/test_gate_python_installs_are_pinned.py fails if either
# installs anything else.
#
# The four lines are the two packages the gate needs and their own dependencies
# that the ASH image does not already carry. git-remote-codecommit also needs
# botocore, which is deliberately absent: ASH depends on boto3, so the base image
# has it, and pip leaves an installed requirement alone even in hash mode.
# Listing it here would pin botocore to a version other than the one the base
# image resolved and make pip replace it. If a base image ever lacks botocore,
# the install fails with "all requirements must have their versions pinned"
# rather than fetching it unverified.
#
# Only the files these builds can install are hashed: the CPython 3.12 glibc
# wheels for x86_64 and aarch64 (the base image is python:3.12-slim-bookworm, and
# both Lambda architectures are supported), the pure-Python wheel where that is
# all there is, and git-remote-codecommit's sdist, its only distribution. Hashing
# every published file would have cost about 14 KB, and the CDK build inlines
# this into a template that must stay under CloudFormation's 51,200-byte
# template-body cap. A base image on another Python fails the install with a
# hash mismatch rather than picking up an unverified wheel; re-take the hashes.
#
# To change a version, take each kept file's sha256 from
# https://pypi.org/pypi/<name>/<version>/json (the `urls[].digests.sha256` of the
# filenames described above).
