# Configuration reference

This page is generated from the configuration models in the ASH source code by `scripts/generate_config_reference.py`. Edits made to this file by hand are overwritten the next time it is generated.

Every key is listed with its type, default and the description the model carries. A key whose model has no description says so. Keys inside a list are written `key[].field`: `global_settings.suppressions[].rule_id` is the `rule_id` of one entry in the `suppressions` list. A default written as from `NAME`, else `value` is read from that environment variable when ASH starts; `value` applies when the variable is not set.

## Where ASH finds its configuration

A path given with `--config` or `-c` or the `ASH_CONFIG` environment variable is used as is, and nothing is discovered.

Otherwise ASH looks in the scan's source directory and uses the first of these it finds. Sources are never merged: every other one that exists is ignored, with a warning naming it.

1. `.ash.yml`
2. `.ash/.ash.yml`
3. `.ash.yaml`
4. `.ash/.ash.yaml`
5. `.ash.json`
6. `.ash/.ash.json`
7. `ash.yml`
8. `.ash/ash.yml`
9. `ash.yaml`
10. `.ash/ash.yaml`
11. `ash.json`
12. `.ash/ash.json`
13. `.ashrc.toml`
14. `.ashrc.yaml`
15. `.ashrc.yml`
16. `.ashrc.json`
17. `ashrc.toml`
18. `ashrc.yaml`
19. `ashrc.yml`
20. `ashrc.json`
21. `pyproject.toml`

`pyproject.toml` counts only when it has a `[tool.ash]` table; one without it is not a configuration source.

These are read from the source directory only, never from `.ash/`: `.ashrc.toml`, `.ashrc.yaml`, `.ashrc.yml`, `.ashrc.json`, `ashrc.toml`, `ashrc.yaml`, `ashrc.yml`, `ashrc.json`, `pyproject.toml`.

A config file can name base files with `extends`. A chain may be at most 10 levels deep and read at most 50 files.

## Workspace policy file

In workspace mode, policy that applies to every project lives in its own file, separate from any project's configuration.

ASH looks for it at the workspace root and then in `.ash/`, under any of these names: `.ash-workspace.yml`, `.ash-workspace.yaml`, `.ash-workspace.json`, `ash-workspace.yml`, `ash-workspace.yaml`, `ash-workspace.json`.

Exactly one may exist: when ASH finds more than one, it refuses the workspace rather than choose.

### Workspace policy keys

A key not listed here is an error when the configuration is loaded.

<!-- doctest: options of=workspace-policy -->
| Key | Type | Default | Description |
|-----|------|---------|-------------|
| <a id="workspace-policy.workspace"></a>`workspace` | [section](#workspace-section-workspace) | see the section | Workspace-wide policy. Distinct from AshConfig.workspace, which holds execution scheduling knobs in a project config; nothing here can be set from a project's own file. |

### <a id="workspace-section-workspace"></a>Workspace policy `workspace`

Workspace-wide policy: the `workspace` block of the policy file.

A key not listed here is an error when the configuration is loaded.

<!-- doctest: options of=workspace-policy.workspace -->
| Key | Type | Default | Description |
|-----|------|---------|-------------|
| <a id="workspace-policy.workspace.max_severity_threshold"></a>`max_severity_threshold` | one of `ALL`, `LOW`, `MEDIUM`, `HIGH`, `CRITICAL` or null | `null` | The LOOSEST severity threshold any project may use. A project configuring something stricter keeps it; a project configuring something looser is tightened to this value. 'max' refers to permissiveness, not to severity: the strictness order is ALL &lt; LOW &lt; MEDIUM &lt; HIGH &lt; CRITICAL, so raising this value LOOSENS the ceiling. Unset means no ceiling. Case-sensitive. |
| <a id="workspace-policy.workspace.suppressions"></a>`suppressions` | list of [section](#workspace-section-workspace-suppressions) | `[]` | Suppressions that apply across the workspace. Paths are WORKSPACE-relative (e.g. 'api/src/legacy.py') and are rewritten into each project's own coordinates before being applied. A suppression that cannot match inside a project is not passed to it; one that cannot be rewritten soundly refuses the workspace. |
| <a id="workspace-policy.workspace.ignore_paths"></a>`ignore_paths` | list of [section](#workspace-section-workspace-ignore_paths) | `[]` | Paths excluded across the workspace. Workspace-relative and pushed down per project, exactly as 'suppressions' are. |
| <a id="workspace-policy.workspace.additional_scanners"></a>`additional_scanners` | list of string | `[]` | Scanners every project must run, in addition to whatever it enables itself. Additive only -- this cannot disable a scanner a project enabled. A scanner the project already declares runs under the project's own config and its findings are the project's; a scanner added only by this policy runs with default config and its findings are tagged 'origin: workspace-policy' and reported separately. |
| <a id="workspace-policy.workspace.policy_scanners_gate"></a>`policy_scanners_gate` | boolean | `false` | Whether findings from policy-added scanners affect a project's exit code. Default false: a workspace that adds a scanner to gather visibility should not thereby fail projects that never opted into it, and turning it on is the operator saying they have triaged what the new scanner reports. |
