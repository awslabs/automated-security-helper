Each table says what ASH supports, with one row for every item the code knows about. A cell holds a name taken from the code or one phrase from a fixed set, and the notes under a table explain every phrase it uses. A cell never says more than the code states: where a fact was not declared or not measured, the cell says that.

A platform cell shows the first reading that applies, in this order: the scanner's refusal, no asset, off by default, provisioned, package-defined.

`yes`: the scanner's module loads on every scan.

`loads only when its module is listed`: the scanner is in an alpha module, which a scan loads only when `ash_plugin_modules` names the module shown under Module to list.

`provisioned`: ASH downloads a pinned release of the scanner's tool built for this operating system and CPU.

`no asset`: ASH downloads this scanner's tool, and the pinned release has no build for this operating system and CPU.

`refused: <reason>`: the scanner itself states that it cannot run on this operating system, in the words shown.

`off by default`: the scanner's configuration turns it off on this operating system until you enable it.

`package-defined (not declared)`: ASH provisions no download for this scanner, so where it runs is where the package or tool it uses runs, and ASH declares no list of those platforms.

`not measured`: nothing in the code or the register states this fact, so the table does not guess it.

Where each column comes from:

- `Scanner`: The name in the scanner's manifest, which is its name in the config.
- `Tier`: The tier in the manifest. A deprecated scanner names the scanner that supersedes it.
- `Loads on its own`: The manifest: whether the scanner's module loads without being listed in ash_plugin_modules.
- `Module to list`: The manifest's plugin module, which ash_plugin_modules names to load an alpha scanner; a scanner that loads on its own is built in.
- `Install methods`: The runtime kind in the scanner class's operational facets, as the way its tool reaches the machine.
- `Linux x86-64`: The scanner's own refusal of Linux, then whether the facets name a download for linux/amd64, then the scanner's enabled setting on Linux, then the facets' provisionable platforms. The first that applies is shown.
- `Linux arm64`: The scanner's own refusal of Linux, then whether the facets name a download for linux/arm64, then the scanner's enabled setting on Linux, then the facets' provisionable platforms. The first that applies is shown.
- `macOS Intel`: The scanner's own refusal of Darwin, then whether the facets name a download for darwin/amd64, then the scanner's enabled setting on Darwin, then the facets' provisionable platforms. The first that applies is shown.
- `macOS Apple silicon`: The scanner's own refusal of Darwin, then whether the facets name a download for darwin/arm64, then the scanner's enabled setting on Darwin, then the facets' provisionable platforms. The first that applies is shown.
- `Windows x86-64`: The scanner's own refusal of Windows, then whether the facets name a download for windows/amd64, then the scanner's enabled setting on Windows, then the facets' provisionable platforms. The first that applies is shown.
- `Windows arm64`: The scanner's own refusal of Windows, then whether the facets name a download for windows/arm64, then the scanner's enabled setting on Windows, then the facets' provisionable platforms. The first that applies is shown.
- `Linux libc`: Not read: the pinned downloads do not record the C library they link against, so every row says it was not measured.
