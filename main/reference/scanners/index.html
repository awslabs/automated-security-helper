    Scanners reference¶

    This page is generated from the scanner plugins in the ASH source code by scripts/generate_scanner_reference.py. Edits made to this file by hand are overwritten the next time it is generated.

    ASH ships 19 scanners. The built-in ones are loaded on every scan. The others are community scanners, each in a plugin module that ash scan loads only when the configuration's ash_plugin_modules (or --ash-plugin-modules) names the module; for the MCP server, see What a plugin can do.

    Scanner Tool type Enabled by default Provided by Command Runs with --python-only
    actionlint IAC yes built in actionlint no
    bandit SAST yes built in bandit yes
    cdk-nag IAC yes built in python no
    cfn-guard IAC yes built in cfn-guard no
    cfn-lint IAC yes built in cfn-lint yes
    cfn-nag IAC yes built in cfn_nag_scan no
    checkov IAC yes built in checkov yes
    detect-secrets SECRETS yes built in detect-secrets yes
    gitleaks SECRETS yes built in gitleaks no
    grype SCA yes built in grype no
    npm-audit SCA yes built in npm no
    opengrep SAST yes on Linux and macOS; no on Windows built in opengrep no
    semgrep SAST yes on Linux and macOS; no on Windows built in semgrep yes
    syft SBOM yes built in syft no
    trivy SCA yes built in trivy no
    zizmor SAST yes built in zizmor yes
    ferret-scan SECRETS yes community module ash_ferret_plugins ferret-scan no
    snyk-code SAST yes community module ash_snyk_plugins snyk no
    trivy-repo SAST yes community module ash_trivy_plugins trivy no

    Tool type is the scanner's own ScannerToolType. --python-only keeps a scanner when its is_python_only() is true: the scanner class's own python_only when it states one; otherwise only when the scanner runs its tool through uv, declares no install commands, and has only pip dependencies. A scanner it does not keep is SKIPPED.

    Environment in the sandbox¶

    When sandbox.mode confines scanners, a scanner process receives only an allowlist of the environment ASH was started with. Every sandboxed scanner gets these names: COLUMNS, CURL_CA_BUNDLE, FORCE_COLOR, GEM_HOME, GEM_PATH, JAVA_HOME, LANG, LANGUAGE, NODE_EXTRA_CA_CERTS, NO_COLOR, PATH, REQUESTS_CA_BUNDLE, SSL_CERT_DIR, SSL_CERT_FILE, SYSTEMROOT, TERM, TZ, VIRTUAL_ENV; and names starting with LC_, ASH_, UV_, PYTHON. A scanner's own prefixes and names, listed with each scanner below, are added to that. A name containing TOKEN, PASSWORD, PASSWD, SECRET, CREDENTIAL, AUTH, APIKEY, API_KEY, PRIVATE_KEY, SESSION is dropped even under an allowed prefix, unless the scanner names it exactly. The proxy variables HTTPS_PROXY, HTTP_PROXY, NO_PROXY, http_proxy, https_proxy, no_proxy are passed only to a scanner that has a network. The lists are in automated_security_helper/utils/sandbox/policy.py.

    The network entry of each scanner below is its default. sandbox.network_scanners, when it is set, replaces every scanner's declared need: only the scanners it names get a network. A config file inside a git checkout or the scanned directory can only take network away, and an offline scan gives no scanner a network.

    Option Type Default Description

Set by such a config, it is ignored with a warning.
    include_checks list of string [] cfn-lint rule ids or prefixes to enable in addition to the defaults, e.g. ['I'] for informational rules.
    honor_inline_ignores boolean false Honor the ignore_checks and configure_rules a template sets for itself in Metadata: cfn-lint: config (ignore_checks also at the resource level). Off by default: every rule outside ignore_checks and the config_file's ignore_checks is passed to cfn-lint as mandatory, and the config_file's configure_rules are passed on the command line, which cfn-lint takes instead of a template's, so a template cannot hide its own findings or the next template's parse errors, which reach ASH, where suppressions are reported and counted. A config_file setting the command line cannot carry (a list of more than one item, or a value with a comma, colon or equals sign) is then left out with a warning, and a config_file that sets merge_configs fails the scan. On, each template is linted by a cfn-lint run of its own, so its settings reach no other template; that adds a cfn-lint start-up per template. Used only when the operator sets it, with --config-overrides or in a config file outside every git checkout and the scanned directory: a config file inside one, or one an MCP client delivered, does not choose it. Set by such a config, it is ignored with a warning.
    tool_version string or null ">=1.43.3,<2.0.0" Version constraint for the cfn-lint installation, in pip requirement syntax. The default is the range the scanner's SARIF handling was verified against. Used only when the operator sets it, with --config-overrides or in a config file outside every git checkout and the scanned directory: a config file inside one, or one an MCP client delivered, does not choose it. Set by such a config, it is ignored with a warning.

A scan whose output is larger fails and records no findings, with an error that names this option. Honored only from --config-overrides or a config file outside the scanned tree.

    severity_threshold one of ALL, LOW, MEDIUM, HIGH, CRITICAL, or null null Minimum severity level to consider findings as failures. This is a scanner-level override of the default severity-level within ASH of MEDIUM.
    scan_timeout integer or null, at least 1 1800 Maximum time in seconds to allow this scanner's tool invocation to run before it is killed. Set to null to leave the scanner unbounded, which risks a scan that never completes.
    offline boolean false Run this scanner offline even when ASH runs online. False follows ASH's own mode; it never puts a scanner online under --offline.
    honor_tree_exclusions boolean false Let snyk code test apply the exclusion files it finds in the scanned tree: the exclude.code and exclude.global entries of a .snyk file and the rules of a .dcignore file, which leave the files they name out of the analysis. snyk has no option that stops it reading them, so while this is false and the tree has one, snyk-code does not run and its error names the files. Used only when the operator sets it, with --config-overrides or in a config file outside every git checkout and the scanned directory: a config file inside one, or one an MCP client delivered, does not choose it.

    trivy-repo¶

    • Scanner page: trivy-repo scanner page
    • Class: automated_security_helper.plugin_modules.ash_trivy_plugins.trivy_repo_scanner.TrivyRepoScanner
    • Provided by: community module ash_trivy_plugins, which ash scan loads when ash_plugin_modules names automated_security_helper.plugin_modules.ash_trivy_plugins
    • Enabled by default: yes
    • Tool type: SAST
    • Command: trivy
    • Install: pinned, checksum-verified release of trivy by ash dependencies install, for darwin/amd64, darwin/arm64, linux/amd64, linux/arm64, windows/amd64
    • Offline strategy: cache_flags
    • Network in the sandbox, by default: yes, unless the scan is offline
    • Environment passed into the sandbox: TRIVY_*
    • Environment set under sandbox-exec: none

    Options, under scanners.trivy-repo.options. An option not listed here refuses the configuration.

    Option Type Default Description
    severity_threshold one of ALL, LOW, MEDIUM, HIGH, CRITICAL, or null null Minimum severity level to consider findings as failures. This is a scanner-level override of the default severity-level within ASH of MEDIUM.
    scan_timeout integer or null, at least 1 1800 Maximum time in seconds to allow this scanner's tool invocation to run before it is killed. Set to null to leave the scanner unbounded, which risks a scan that never completes.
    offline boolean false Run in offline mode, skipping DB updates and check-update calls. When true, this scanner runs offline even if ASH does not. ASH's own offline mode (--offline or ASH_OFFLINE) applies whatever this is set to; false follows it.
    scanners list of one of vuln, misconfig, secret, license ["vuln", "secret", "misconfig", "license"] List of what security issues to detect with Trivy Repo specifically
    license_full boolean true Eagerly look for licenses in source code headers and license files
    ignore_unfixed boolean true Display only fixed vulnerabilities
    disable_telemetry boolean true Disable sending anonymous usage data to Aqua (--disable-telemetry). Only the operator sets it to false, with --config-overrides or in a config file outside every git checkout and the scanned directory: a config file inside one, or one an MCP client delivered, may set it to true but not to false. Offline, trivy sends none whatever this says.
    config_file path, string, or null null A trivy config file (trivy.yaml), passed as --config. Used only when the operator sets it, with --config-overrides or in a config file outside every git checkout and the scanned directory: a config file inside one, or one an MCP client delivered, does not choose it. The file is used only when it is outside the scanned tree; otherwise it is ignored with a warning. A relative path is taken from the directory of the config file that sets it, or from the working directory for --config-overrides, not from the source directory. Unset or ignored, ASH passes TRIVY_CONFIG when that names a file outside the scanned tree (a relative path in it is taken from the working directory), and otherwise an empty config of its own, so trivy does not load a trivy.yaml from the directory it runs in. A path that does not exist fails the scan.
    module_dir path, string, or null null A directory of trivy modules, passed as --module-dir. Unset, ASH passes an empty directory of its own. Used only when the operator sets it, with --config-overrides or in a config file outside every git checkout and the scanned directory: a config file inside one, or one an MCP client delivered, does not choose it. The directory is used, and a relative path taken, as for config_file. A path that is not a directory fails the scan.
    ignore_file string or null null A trivy ignore file, passed as --ignorefile. Used only when the operator sets it, with --config-overrides or in a config file outside every git checkout and the scanned directory: a config file inside one, or one an MCP client delivered, does not choose it. The file is used only when it is outside the scanned tree; a relative path is taken from the directory of the config file that sets it, or from the working directory for --config-overrides and the environment variable. Unset, TRIVY_IGNOREFILE is used the same way, and otherwise trivy gets an empty one, so a .trivyignore in the scanned repository does not remove findings.
    secret_config_file string or null null A trivy secret scanning config (trivy-secret.yaml), passed as --secret-config. Used only when the operator sets it, with --config-overrides or in a config file outside every git checkout and the scanned directory: a config file inside one, or one an MCP client delivered, does not choose it. The file is used only when it is outside the scanned tree; a relative path is taken from the directory of the config file that sets it, or from the working directory for --config-overrides and the environment variable. Unset, TRIVY_SECRET_CONFIG is used the same way, and otherwise trivy gets an empty one, so a trivy-secret.yaml in the scanned repository does not disable secret rules.
