    ash config lint¶

    Lint an ASH configuration file for issues and optionally auto-fix them.

    This command performs all validation checks plus additional lint checks:

    • Internal-only fields in scanners/reporters/converters
    • Invalid or unknown top-level sections
    • Duplicate field definitions
    • Suppressions with line_start but missing line_end
    • Expired suppressions
    • Suppression reasons spanning multiple lines
    • Unused suppressions (from last scan report)

    Use --fix to auto-fix common issues (removes internal fields, sets missing line_end, removes expired suppressions, collapses multi-line reasons).

    Use --fix-unused to comment out suppressions that no longer match any finding (based on the unused suppressions report from the last scan).

    Use --non-interactive (or --yes/-y) to skip confirmation prompts. This is useful for pre-commit hooks or CI/CD pipelines.

    Exit codes: 0 a scan accepts the config (whatever else is reported is a warning); 1 no config file was found, or --fix or --fix-unused refused to rewrite it; 3 a scan would refuse the config, as 'ash config validate' reports it, the file does not parse, or the named file does not exist or cannot be read. The output marks each issue that makes a scan refuse the config with "blocks the scan".

    Examples:

    # Lint the default config
ash config lint

# Lint and auto-fix issues
ash config lint --fix

# Lint, fix, and remove unused suppressions
ash config lint --fix --fix-unused

# Non-interactive mode for pre-commit
ash config lint --fix --fix-unused --non-interactive

# Lint a specific config file
ash config lint --config path/to/config.yaml

    ash config lint [OPTIONS]
    Option Type Default Environment variable Description
    --config, -c text not set ASH_CONFIG The path to the configuration file. By default, the config a scan of the current directory would use: ['.ash.yml', '.ash.yaml', '.ash.json', 'ash.yml', 'ash.yaml', 'ash.json'] (each at the root, then in .ash/), then ['.ashrc.toml', '.ashrc.yaml', '.ashrc.yml', '.ashrc.json', 'ashrc.toml', 'ashrc.yaml', 'ashrc.yml', 'ashrc.json'] at the root, then the tool.ash table of pyproject.toml at the root; the first found is used.
    --output-dir, -o text not set Path to the ASH output directory (for unused suppressions report). Defaults to .ash/ash_output
    --fix flag off Auto-fix fixable issues (internal fields, missing line_end, expired suppressions, multi-line suppression reasons). A TOML file, and a file that reads the environment (${VAR} or !ENV), are not rewritten: fix those by hand
    --fix-unused flag off Comment out unused suppressions based on the last scan's unused suppressions report. A TOML file, and a JSON file (which holds no comments), are not rewritten: remove those by hand
    --non-interactive, --yes, -y flag off Accept all changes without prompting. Useful for pre-commit hooks and CI/CD
    --source-dir text not set ASH_SOURCE_DIR The directory a scan would scan, as ash scan --source-dir: the config is discovered there unless --config names one, and a config inside it may only extend files inside it. Defaults to the current directory.
    --verbose, -v flag off Enable verbose logging
    --debug, -d flag off Enable debug logging
    --color / --no-color flag on Enable/disable colorized output

    ash config update¶

    Update an existing configuration file with the specified modifications.

    ash config validate¶

    Validate an ASH configuration file the way a scan loads it.

    The file is loaded as a scan loads it: parsed (with ${VAR} and !ENV references resolved), its extends chain followed, and checked against the AshConfig model the JSON schema is generated from, with strict types. A config a scan would refuse is reported with every field it refuses, and the command exits 3, the exit code a scan gives for an invalid configuration.

    It also warns about things a scan accepts but that are probably mistakes: internal-only fields in scanners/reporters/converters, unknown or internal top-level sections, duplicate top-level keys, a missing project_name, and directory paths without a '**' glob. Warnings do not change the exit code; 'ash config lint' reports the same checks and can fix some of them, with one exception: lint judges the file as written, so it reads neither --config-overrides nor ASH_PLUGIN_MODULES, and an input this command refuses for an environment-named module can still lint clean.

    Exit codes: 0 valid (warnings may be printed), 1 no config file found and none of the scan's other inputs given (--config-overrides, ASH_PLUGIN_MODULES), 3 invalid, or the named config file does not exist or cannot be read. A file that does not parse is invalid too, and a scan refuses it as well. With --config-overrides or ASH_PLUGIN_MODULES and no config file, the default configuration with those scan inputs applied is validated -- the config a scan of the directory would run with, and the one ash config get prints or refuses for the same input, exiting 3 when the environment names a module the scan's plugin loader refuses.

    Examples:

    # Validate the config a scan of the current directory would use
ash config validate

# Validate specific config file
ash config validate --config path/to/config.yaml

# Validate with the overrides a scan will be given
ash config validate --config-overrides 'fail_on_findings=false'

    ash config validate [OPTIONS]
    Option Type Default Environment variable Description
    --config, -c text not set ASH_CONFIG The path to the configuration file.     ash inspect findings¶

    The inspect findings command provides an interactive TUI to explore the findings and identify actions to quickly take.

    A finding's code is the code snippet the results hold, wherever the results file is. For a finding with none, its lines are read from its file only when the results file sits in <root>/.ash/ash_output, and only from a regular file inside <root> (a hard link inside the tree counts as a file in it, as it does for the scanners); otherwise the detail view says "(source not shown)".

    ash inspect findings [OPTIONS]
    Option Type Default Environment variable Description
    --output-dir path not set Path to the output directory containing an ASH Aggregated Results JSON report file to analyze.
    --report-file text ash_aggregated_results.json Name of the report file to analyze. Defaults to 'ash_aggregated_results.json'.
    --config, -c path not set ASH_CONFIG Path to the configuration file where suppressions should be saved.     ash merge¶

    Merges the results of a sharded scan into one unified report.

    Pass one --results per shard. The command refuses to merge a set of shards that does not reconstruct exactly one whole scan, and its exit code is the verdict for the union — a shard that owned no failing scanner exits 0, so CI must gate on this command rather than on per-shard success.

    ash merge [OPTIONS]
    Option Type Default Environment variable Description
    --results text, repeatable required A shard's ash_aggregated_results.json, or a directory containing one. Repeat once per shard.
    --output-dir text required ASH_OUTPUT_DIR Directory to write the merged results and reports to.
    --output-formats text, repeatable not set Comma-separated report formats to generate. Defaults to the formats the scan's own configuration asks for.
    --config, -c text not set ASH_CONFIG The operator's config file. Its values replace the shards' for the settings a shard's recorded config cannot choose, such as where reporters send findings and which off-host reporters run. Its ash_plugin_modules are the plugin modules the merge loads, with any --config-overrides adds; a module only the shards recorded is not loaded. It adds no reporter section the shards did not record; use --config-overrides for that.
    --config-overrides text, repeatable not set Configuration overrides as key-value pairs (e.g., 'reporters.s3.enabled=true'), applied over the shards' recorded config.
    --min-severity one of critical, high, medium, low, none low Minimum severity that counts as actionable for the exit code.
    --ignore-suppressions flag off Ignore all suppression rules and report every finding regardless of suppression status. Mirrors 'ash scan --ignore-suppressions', so the same tree gives the same verdict sharded or not.
    --fail-on-findings / --no-fail-on-findings flag not set Exit non-zero when the merged report has actionable findings. Defaults to the scan configuration's value, then to true.
    --fail-on-incomplete-scanners / --no-fail-on-incomplete-scanners flag not set Refuse the merge when a shard completed none of the scanners it owned, and exit 1 when any scanner in the union is ERROR or MISSING, or when every one is SKIPPED, such as when no selected scanner had a file to scan. On by default: under --no-fail-on-incomplete-scanners, a shard whose scanners never ran contributes no findings and the merged report reads as a complete, clean scan. Defaults to the scan configuration's value, then to true; pass --no-fail-on-incomplete-scanners to merge a partial union anyway.
    --log-level one of QUIET, SIMPLE, ERROR, INFO, VERBOSE, DEBUG, TRACE INFO Set the log level.
    --verbose, -v flag off Enable verbose logging
    --debug, -d flag off Enable debug logging
    --color / --no-color flag on Enable/disable colorized output
    --cli-json-input text not set Read parameter values from a JSON object: a path, a file:// URI, or '-' for stdin. Keys are parameter names (output_dir) or long flag spellings (--output-dir).     Scan code, infrastructure, secrets, and dependencies.

    Start with: ash --mode container --source-dir .
