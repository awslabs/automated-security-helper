## Recorded checkov version names the copy that runs (#955, acceptance item 2)

Closes the second acceptance item of #955, which #956 explicitly left open.

### What was wrong

With no checkov in uv's tools directory, the dependency check's `uv tool run --from <spec> checkov --version` probe resolves a fresh environment (3.4.5 in the report) while the scan runs the verified copy on PATH (3.3.15). `_select_tool_execution` already overwrote the recorded `tool_version` with the PATH copy's own `--version` answer. When that copy verified but its answer carried no version line, the overwrite was skipped and the uv probe's 3.4.5 stayed as the version of a 3.3.15 run.

### Change

In the satisfied branch of `UVToolMixin._select_tool_execution`, `tool_version` is now the executed copy's version or None, never the uv probe's value. The deferred uv probe is cleared there too: it is not owed on a route that no longer uses uv.

### Tests

`tests/unit/plugin_modules/ash_builtin/scanners/test_checkov_records_the_version_of_the_copy_it_runs.py` (3 cases): the copy's version replaces the probe's; a copy with no version answer does not keep the probe's value (red on the test-only commit: `tool_version` stayed `'3.4.5'`); a later deferred probe does not rewrite the copy's record.
